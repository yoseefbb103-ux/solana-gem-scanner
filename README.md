# ماسح إشارات سولانا

لوحة مراقبة **للقراءة فقط** لرصد أزواج توكنات سولانا الجديدة وترتيبها وفق بيانات سوق وأمان عامة قابلة للمراجعة. لا تربط هذه النسخة أي محفظة، ولا توقّع معاملات، ولا تنشئ أوامر شراء أو بيع، ولا تتعامل مع مفاتيح خاصة.

> **تحذير مالي:** هذا تحليل آلي لبيانات عامة عالية التذبذب، وليس توصية شراء أو بيع أو احتفاظ، وليس ضمان عائد أو حماية من الخسارة. لا تعني حالة «بيانات متوازنة» أن التوكن آمن أو مناسب للتداول.

## الرصد المبكر المتدرج

يعمل عامل Render في دورتين متتابعتين لا تعملان بالتوازي. تجلب دورة **الرصد المبكر** ملفات DEX Screener الحديثة كل 20 ثانية، وتطلب أزواجاً لمجموعة صغيرة فقط، ثم تحفظ الأزواج ذات السيولة الأولية التي تبلغ 1,000 دولار أو أكثر في `earlyTokenWatches`. لا تقيّم هذه الدورة العقد أو السعر عبر Jupiter، ولا تطلق على الناتج إشارة دخول.

تعمل دورة **الفحص المؤكد** بوتيرة مستقلة لا تقل عن 60 ثانية وتطبّق تقارير RugCheck، وقياسات السيولة، ومقارنة Jupiter عندما تتاح، ثم تعلن `CONFIRMED ALERT` فقط لعنصر كان مرصوداً أولياً واجتاز جميع البوابات: قرار «مراقبة»، تقرير أمان مارّ، سيولة لا تقل عن 10,000 دولار، سعر Jupiter متاح، فرق سعر لا يتجاوز 12%، وعدم وجود سحب سيولة مرصود. تحفظ اللوحة زمن أول رصد وزمن التأكيد لتظهر زمن الانتقال. يُطالب سجل الرصد بالتأكيد ذرياً مرة واحدة فقط، ويُحفظ حدث التنبيه الداخلي في معاملة قاعدة البيانات نفسها؛ فلا يعاد تنبيه التأكيد في دورة لاحقة ولا يترك فشل كتابة الحدث مرحلةً مؤكدةً بلا سجل داخلي. يبقى تسليم Telegram محاولة منفصلة بعد ذلك تُسجَّل نتيجتها (`sent` أو `failed` أو `skipped`) ولا تعني نجاحه ضمان وصول الرسالة. لا تعني أي من المرحلتين توصية شراء أو توقع عائد.

عند تقييد DEX Screener أو بطء المصدر، يرفع العامل فاصل كل دورة تدريجياً ثم يعيده تدريجياً عند الاستقرار. يبقى قفل قاعدة البيانات المشترك فعالاً على الدورتين والفحص اليدوي، ولذلك لا ينفذ فحصان حقيقيان في اللحظة نفسها.

## بيانات تحضيرية للفحص العميق

تحتوي لقطات الفحص وتقارير الأمان على `holderClusterScore` و`bundleDetected` و`washTradingScore` و`fundingSourceOverlap` و`fundingEvidenceStatus` و`token2022Flags` و`lpBurnVerified`. يملأ الفحص العميق الحالي جميعها حيث يتاح دليل RPC أو سجل مفهرس. يميز `fundingEvidenceStatus` بين **تداخل مرصود** و**عدم رصد ضمن نافذة مفهرسة** و**عدم رصد ضمن نافذة RPC عامة محدودة** و**تعذر المصدر**؛ لا تتحول أي من حالتي عدم الرصد إلى شهادة أمان. يبقى `washTradingScore` محايداً حتى يتوفر تحليل معاملات موثق؛ لا يعامل الحقل الفارغ كإشارة أمان أو خطر.

## كيف تعمل طبقة الأمان؟

يعد RugCheck مصدر الأمان الأساسي لأن تقرير التوكن العام يوفر حالة صلاحيات mint/freeze، المخاطر، الأسواق، السيولة، الحائزين وعنوان المنشئ. [2] لا يحوّل التطبيق أي من هذه الحقول إلى «شهادة أمان»: خطأ الشبكة أو نقص البيانات يظل حالة غير متاحة، ويضيف التطبيق خطراً محدوداً بدلاً من علامة اجتياز.

لا يعتمد تاريخ الناشر على عدّ معاملات RPC سطحية. عندما تعيد RugCheck حقل `rugged` أو خطراً يحمل دلالة `rugged` لعنوان منشئ، يسجل العنوان مع تاريخ أول رصد في جدول محلي تراكمي. عند ظهور العنوان في فحص لاحق، تضيف اللوحة تحذيراً مؤرخاً وتفرض قرار «تجنب». لا يمثل عدم وجود العنوان في الجدول دليلاً على سلامة الناشر؛ فهو يعكس فقط ما تراكم من فحوص التطبيق السابقة. [3]

## منهجية التقييم

درجة الفرصة ودرجة المخاطرة تتراوحان بين 0 و100. درجة الفرصة هي **فرز قابل للتفسير** وليست توقع سعر؛ ودرجة المخاطرة لا تقيس كل مخاطر العقد أو السوق.

| العامل | أثره في الفرصة | أثره في المخاطرة |
| --- | --- | --- |
| السيولة وحجم الساعة | يكافئ قابلية التداول النسبية والنشاط المتوازن | السيولة المحدودة أو الحجم المتطرف مقارنة بالسيولة يزيدان المخاطرة. |
| عمر الزوج | يكافئ حداثة ضمن نافذة متوازنة | الأزواج شديدة الحداثة أكثر هشاشة. |
| الصفقات والزخم | يكافئ نشاطاً متكرراً وزخماً إيجابياً متسقاً بين 1س و6س و24س | تغيرات 5د/1س الحادة أو زخم سلبي متعدد الأطر ترفع المخاطرة. |
| الانزلاق التقريبي | يعرض شفافية إضافية فقط | يحذّر من قابلية تداول أضعف عند أحجام 200 و500 دولار الافتراضية. |
| فرق Jupiter / DEX Screener | لا يرفع الفرصة | فرق يتجاوز 12% يطلق تحذيراً لمراجعة السعر يدوياً. |
| تعدد المنصات والبيانات الوصفية | يضيفان نقاطاً محدودة فقط عند وجود سيولة معتبرة عبر أكثر من DEX أو اكتمال حقول عامة | لا يخفضان المخاطرة ولا يمثلان دليلاً على الموثوقية. |
| الأمان | لا يرفع الفرصة لمجرد عدم وجود تحذير | صلاحيات العقد وLP والحيازات والناشر والانتحال تضيف جزاءً مستقلاً للمخاطرة. |

## التشغيل المحلي

يتطلب المشروع Node.js 22.13.0 وقاعدة بيانات MySQL أو TiDB متوافقة و`pnpm`.

```bash
git clone https://github.com/YOUR_GITHUB_USERNAME/solana-gem-scanner.git
cd solana-gem-scanner
corepack enable
pnpm install --frozen-lockfile
export DATABASE_URL='postgresql://USER:PASSWORD@HOST:5432/solana_scanner'
export JWT_SECRET='replace-with-a-long-random-secret'
pnpm drizzle-kit migrate
pnpm dev
```

للتأكد من جودة الكود:

```bash
pnpm test
pnpm check
```

للتحقق الصريح من اتصال رمز تيليجرام بعد ضبط الأسرار، استخدم الآتي. هذا الاختبار معزول عن مجموعة الاختبارات المعتادة كي لا تفشل عمليات البناء بسبب انقطاع عابر في واجهة خارجية:

```bash
VERIFY_TELEGRAM_CREDENTIALS=1 pnpm vitest run server/telegram.credentials.test.ts
```

## حدود الاكتشاف والعامل الخلفي

لا يشغّل `pnpm dev` العامل تلقائياً حتى لا ينشئ فحصاً مستمراً على جهاز المطور. استخدم الخدمة المستقلة التالية في Render، أو شغّلها محلياً في طرفية ثانية بعد البناء:

```bash
pnpm build
pnpm start:worker
```

لاختبار دورة عامل واحدة محلياً دون إبقائه قيد التشغيل، استخدم `WORKER_RUN_ONCE=1 pnpm start:worker` بعد البناء.

العامل لا ينفّذ صفقات؛ وظيفته الوحيدة جلب البيانات وتقييمها وتخزينها وإرسال تنبيه مشروط عند ضبطه.

قد يبدأ المستخدم تحديثاً يدوياً حين يعمل العامل في الخلفية، أو يرسل طلبين متقاربين. القفل المشترك في قاعدة البيانات يمنع تشغيل خطّي فحص متوازيين في هذه الحالة، بما يشمل خدمة الويب والعامل المنفصل. انتهاء القفل بعد خمس دقائق آلية تعافٍ من توقف غير متوقع وليست دليلاً على نجاح الفحص السابق.

تستخدم فحوص المرحلة العميقة Helius أولاً عندما يوجد `HELIUS_API_KEY` على الخادم، ثم نقطة Solana الرسمية وPublicNode كبدائل للقراءة فقط. يوفر Helius نقطة RPC أكثر استقراراً وسجل معاملات مفهرساً للتحقق من مصدر التمويل لأكبر خمسة حائزين. تسلسل الوحدة الطلبات، وتبدّل النقطة تلقائياً عند `429` أو `403` أو تعذر الشبكة، وتمنح كل مرشح عميق ميزانية زمنية قصوى قدرها 18 ثانية؛ عند تجاوزها تظهر نتيجة «غير متاح» ولا تتعطل دورة العامل. من دون المفتاح يفحص النظام أعمق مرشحين فقط في كل دورة لتجنب استنزاف البنية العامة؛ وعند وجوده يطبق حد `deepScanLimit` الكامل. لا يظهر المفتاح في المتصفح أو GitHub. لا يدّعي أي مسار إثبات الملكية الحقيقية للحسابات أو تحويل فجوة في السجل إلى نتيجة «آمنة». [11] [12]

لا تحتوي بيانات زوج DEX Screener العامة على حقل موثق يثبت انتقال توكن من منحنى Pump.fun إلى Raydium؛ فـ`dexId` ووقت إنشاء الزوج لا يكفيان لإثبات الهجرة. لذلك لا تعرض اللوحة عامل «تخرج Pump.fun إلى Raydium» من هذا المصدر وحده، بدلاً من استنتاج مضلل. [1]

## النشر على Render

يستخدم البناء `vite build` للواجهة وesbuild لخادمي الويب والعامل؛ لذلك يكون ملف خدمة الويب في `dist/_core/index.js` والواجهة الثابتة في `dist/public`. يطابق script `start` هذا المسار، بينما يشغّل `start:worker` الملف `dist/worker.js`. هذا التطابق ضروري حتى ينجح فحص المنفذ 3000 في Render.

يعرف `render.yaml` خدمتين منفصلتين: خدمة الويب وخدمة Worker دائمة. استخدم **New → Blueprint** بعد ربط مستودع GitHub. يدعم Render تعريف خدمات الويب والعامل وأوامر البناء والتشغيل ومتغيرات البيئة داخل ملف Blueprint. [4]

| المتغير | خدمة الويب | خدمة العامل | ملاحظات |
| --- | --- | --- | --- |
| `DATABASE_URL` | مطلوب | مطلوب | رابط MySQL/TiDB نفسه لكلا الخدمتين. |
| `JWT_SECRET` | مطلوب | غير مطلوب | يولّد Render قيمة للخدمة الويب. |
| `TELEGRAM_BOT_TOKEN` | اختياري | اختياري | رمز Bot API؛ لا تضعه في GitHub أو `render.yaml`. |
| `TELEGRAM_CHAT_ID` | اختياري | اختياري | وجهة تلقي التنبيهات. |
| `HELIUS_API_KEY` | اختياري | اختياري | مفتاح مجاني، خادمي فقط، لفحص RPC مستقر وسجل التمويل المفهرس. غيابه لا يوقف الماسح. |
| `SOLANA_RPC_URL` | اختياري | اختياري | نقطة RPC متوافقة للقراءة فقط؛ الافتراضي هو نقطة Solana العامة. |

يراعي ملف النشر إصدار Node عبر `NODE_VERSION`، وهو أسلوب مدعوم في Render. [5] بعد أول نشر، راقب سجل Worker للتأكد من أن الفحص يجري بفاصل مناسب وأن قاعدة البيانات مشتركة مع خدمة الويب.

## رفعه إلى GitHub

أنشئ مستودعاً فارغاً ثم نفّذ الأوامر التالية من جذر المشروع بعد استبدال الرابط:

```bash
git init
git add .
git commit -m "Advanced Solana signal scanner"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/solana-gem-scanner.git
git push -u origin main
```

لا ترفع ملف `.env` أو كلمات مرور أو رموز بوت أو روابط قواعد البيانات التي تتضمن بيانات دخول. غيّر أي رمز بوت ظهر في محادثة أو سجل قبل استخدامه في الإنتاج.

## البنية

```text
client/                       واجهة React/Tailwind وDashboard وPerformance
server/scanner/               سوق DEX Screener، RugCheck، فحص Solana RPC العميق، الدرجات وخدمة الفحص
server/worker.ts              عامل Render التكيفي المستقل
server/telegram.ts            إرسال اختياري من الخادم فقط
server/scannerDb.ts           اللقطات، الأمان، الصحة، المتابعة، الأداء والتنبيهات
server/routers/scanner.ts     واجهات tRPC العامة للقراءة والإعدادات
drizzle/                      مخطط MySQL وترحيلات البيانات
render.yaml                   خدمتا الويب والعامل في Render
```

### Render Postgres

يستخدم Blueprint قاعدة Render Postgres داخلية ويحقن `DATABASE_URL` تلقائياً في خدمة الويب والعامل. الخطة المجانية مناسبة للاختبار فقط وتنتهي بعد 30 يوماً وفق قيود Render؛ يمكن ترقيتها من لوحة Render عند الحاجة.

## تنبيهات Telegram المصوّرة

يرسل الماسح تنبيهات القراءة فقط بصياغة منظمة تشمل اسم العملة ورمزها ودرجة الفرصة ودرجة المخاطرة والسعر والسيولة وحجم الساعة وعمر الزوج وحالة فحص الأمان وعوامل الدعم والتحذيرات ورابط المصدر والعقد. عند توفر رابط صورة HTTPS موثوق من DEX Screener أو ملف التوكن، يستخدم النظام `sendPhoto` مع caption؛ وإذا رفض Telegram تحميل الصورة أو لم تتوفر، يعود تلقائياً إلى `sendMessage` حتى لا تضيع الإشارة. لا تنفذ الرسالة أي شراء أو بيع ولا تضمن عائداً.
